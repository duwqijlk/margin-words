# Margin Words: project notes

A static reader for English novels, for Chinese junior-high learners. It is a plain Vite + React 19 +
Tailwind 3 + zustand single-page app. It has no AI calls. The reader works fully with no account.
**Stay on Tailwind 3.** 4 needs Chrome 99 for `@layer` and Chrome 111 for the colours it emits, so
it cannot reach the Android e-ink readers some of these students use; v3 writes plain CSS with
physical properties. The theme tokens are the CSS variables in `src/styles.css`, each with an
`-rgb` twin so `bg-paper/90` still works (see `tailwind.config.js`).
Optional accounts (email, password, and sync of shelf, progress, saved words, and settings) are
Cloudflare Pages Functions in `functions/` plus a D1 database. See [docs/ACCOUNTS.md](docs/ACCOUNTS.md).
Do not store ordinary user data in R2. Publicly projected contributor names and avatars are the documented
R2 exception; follow [docs/MAINTENANCE.md](docs/MAINTENANCE.md) for that surface. Books and word lists use
book-pack format for compatibility, but live copies are not in git. **The app has no file import**: books
are added only from Discover by a signed-in reader. A word-list book takes the reader's own EPUB from its
Discover card; a standalone EPUB is never imported as a new book.

## Rules

- Tailwind 3 puts every transform in one `transform` declaration (`--tw-translate-x/-y`, rotate, scale).
  A `@keyframes` that writes `transform` replaces that declaration whole, so the entrance animations
  repeat the translate: `pop-in` starts and ends with
  `translate(var(--tw-translate-x, 0px), var(--tw-translate-y, 0px)) scale(...)`. Drop it and a
  centered dialog paints its corner at the middle of the screen for the length of the animation and
  then jumps into place. Tailwind 4 did not have this problem (`-translate-x-1/2` was the separate
  `translate` property), so the mistake came in with the move to v3.

- The UI has two languages, `en` and `zh`. Every visible string (labels, aria-labels, toasts, errors) goes
  through `useT()` / `tr()` from `src/lib/i18n.ts` and lives in BOTH `src/lib/i18n-en.ts` (plain, simple English)
  and `src/lib/i18n-zh.ts` (simple Simplified Chinese for junior-high students). Both must have the same keys (tsc
  and `npm test` check this). Book content (meanings, paragraph/sentence help, phrases, titles) is English and is
  never translated.
- Chinese text is allowed ONLY in `src/lib/i18n-zh.ts`, `docs/` and `README.zh-CN.md`. No Chinese in other
  files of `src/`, `public/`, `packs/`, `examples/` or `scripts/`. `npm run check:cjk` must pass. (The Chinese
  text of the guide page in the app is in `docs/guide-chrome.json` and built into `dist/kit/`, never stored in `public/`.)
- Never change the reading layout when a panel opens. Panels are overlays. Test with a layout-shift run.
- The pack word lists (`packs/<id>/glossary.json`) are a frozen snapshot of book content (see "Where to
  work"). Do not edit or add them. `node scripts/build-packs.mjs --check` must still pass on what is there.
- No network call may depend on a server of ours except the optional account API on the same Pages
 host (`/api/*`, Pages Functions + D1). The reader may only fetch the catalog and pack files the user
 chose, plus that same-origin account API when someone is signed in. Book files stay on the books host.

- A spine file the chapter list already shows keeps its chapter index and paragraph indexes. Files the reader used to drop (and only those) are extras: own ids `x0`, `x1`, …, spine order, labelled Extra. Word anchors and phrase notes do not resolve on an extra. A contents file with zero paragraphs is not inserted as a numbered chapter. The following non-contents spine files, up to the next contents file, are one extra in that reading-order place, titled with the contents title (`fromToc` on `EpubExtra`). A contents title that is front matter (Cover, Title Page, Copyright, Contents, and the same kind of label) is not recovered: those following files stay separate extras, with the same ids as before. A sentence note may set `chapter` to a recovered id only when `fromToc` is set. A paragraph note may set `chapter` to any extra id (`x2`, `x3`, an appendix included) and is placed by the paragraph-lightbulb rule. A short heading file is not this case, and its split files stay ordinary extras. The empty or one-entry contents fallback (one spine file, one chapter) is unchanged and has no extras. Optional glossary field `"spine": { "merge": { "<dropped href or manifest id>": "<contents chapter href>" } }` appends a dropped file after that chapter's existing paragraphs (`applySpineMerge` in `src/lib/epub.ts`). The file's title is shown as a heading in front of the appended paragraphs when the file does not already have that heading. The heading is not a paragraph and its words are not counted (`data-merge-title`), so paragraph indexes and word occurrences stay put. A merge key may name the empty contents file or a content file absorbed into that extra; either name, or both, appends that extra once. A name that matches no spine item is a warning from the glossary check, and it names the key. A key that matches a spine item but merges nothing into or from that file warns too (`spine.merge key "<key>" matches a spine item but nothing is merged into or from it.`). The command-line check prints it, and the app shows it in the own-EPUB dialog (the one place a reader pairs a book with a list). The checker is `scripts/validate-glossary.mjs` in a git checkout, not in `dist/` or the kit zip: `node scripts/validate-glossary.mjs book.epub glossary.json` from the repository root. The validator accepts the field. Do not put it into a pack glossary by hand; teachers add it for the books that need it (Magic Tree House 33 `split_009`, Wings of Fire 3 `part0006_split_001` and `part0005_split_001`, Wings of Fire 4 `split_013`, Wings of Fire 5 `split_014`). Optional top-level `"segmentation": 2` splits a chapter-wrapper blockquote (a `calibre` class, or a blockquote that contains an `h1`–`h4`) into its headings and paragraphs (`skipNestedParagraph` in `src/lib/flow-text.ts`). Without that field a blockquote stays one paragraph, byte for byte the same as before, so a live note on `c2.p0` stays on `c2.p0`. Magic Tree House 33 sets the field. Magic Tree House 17 and 24 leave it off until their notes are re-anchored. `node scripts/seg-report.mjs <epub> <glossary.json>` prints chapter ids, segment ids, a hash per chapter, and whether segmentation is on.
- Glossary entries may carry `senseOnly: true` (optional boolean; docs/GLOSSARY_FORMAT.md 7.5, docs/book-pack-spec.md 4.7). Such an entry holds only position-based senses, and the reader underlines/opens the word ONLY at the places its senses name (`readingHtml`, `entryAppliesAt` in `src/lib/glossary-format.ts`). The flag must survive every copy of the list: validator (`validateGlossary`), `applyGlossary`, `applyPackGlossary`, and the stored `Gloss` in IndexedDB (`gloss:<bookId>`). `node scripts/sense-only-e2e.mjs` checks this end to end (needs the e2e preview server, see `scripts/e2e-ui.mjs`).
- For anyone (or any AI) who makes packs: `docs/book-pack-spec.md`. Keep it in step with `src/lib/glossary-format.ts`; `npm run check:example` validates its JSON example.

## App structure notes

- Pronunciation is one voice at a time, and every recording comes from `https://uapis.cn/api/v1/dictionary/audio` (`src/components/ui.tsx`). The request is keyless and public: no credential is shipped and no key rotation is used, and it is a direct `<audio src>` because a JavaScript `fetch()` from a different origin fails CORS. Explicit UK/US IPA controls ask for `accent=uk` or `accent=us` and never substitute the other accent, a generic recording, or SpeechSynthesis; they show visible failure with retry when media does not start. Generic `speakEnglish` reads the persisted Settings pronunciation preference (US by default), tries that accent before the other uapis accent, and only then uses a device English voice preferring the selected accent. The audio element is APPENDED to the document (hidden) before `play()` because detached audio does not start on some Android WebViews. The query keeps every letter - `voiceText` trims edge punctuation but preserves Unicode such as `café` - and the IPA itself is never sent. `npm run test:pronounce` covers generic phrase/plain-word playback, fallback order, direct URL/accent mapping, attached media, errors/timeouts, cancellation and stale callbacks. The provider rate-limits dynamically rather than exposing a fixed daily allowance; the client makes one request per tap and does not auto-retry in a loop.
- `src/lib/polyfills.ts` only runs because `main.tsx` CALLS `installPolyfills()`. `package.json` says `sideEffects: false`, so a bare `import "@/lib/polyfills"` is dropped from the bundle: the shelf kept working (it touches nothing newer) and opening a book threw `Object.fromEntries is not a function`, a white page with no message. Keep the call, and add a polyfill here - not a newer API - when a device needs one. `crypto.randomUUID` (Chrome 92) is polyfilled there because adding a book and saving a word mint ids with it.
- Routes: `/shelf`, `/discover`, `/dashboard`, `/guide`, `/words`, `/read/<bookId>` (`src/lib/router.ts`, History API; `/` redirects to `/shelf`). The menu is Shelf, Discover, then Overview last. The notebook is a small header button, not a tab. Language is chosen in Settings, not in the header. Overview is `/dashboard`. `/about` is the old About page and opens `/guide`. `/thanks` opens `/dashboard`. The supporters stay at the bottom of the Overview page as one quiet line — names without amounts, plus a count (`{n} supporters`) — with a small `Support us` link that opens the sponsor dialog: the gift is a public-interest donation, the reader picks WeChat, Alipay, or cryptocurrency, and the official address `xcrunnnn@outlook.com` is shown. The thank-you name is the account nickname. The dialog does not ask for another name. Amounts are never shown outside /admin. The site does not take payment and does not email. `/admin` lists requests for that admin account only. The admin ticks email sent, types a USD amount, and ticks the row onto the list. Repeat gifts add up. The six library counts are the visual center of the page, shown large. The page fits one screen. The notebook button does not show a due count. The Guide is opened from Settings, not from the menu. Pages are lazy chunks. `public/_redirects` is the SPA fallback; `public/_headers` sets `no-cache` for the shell and `immutable` for `/assets/*`. The service worker does not answer requests, so a normal refresh is the browser's own load. On activate it turns navigation preload off, claims clients, then deletes every cache. `_headers`/`_redirects` are never part of the app shell. The static kit page is `/kit/`.
- On wide screens (`lg`, 1024px and up) the reading column stays centered at the text-width setting. The word, phrase, and paragraph cards float over the text near the tapped word and do not cover that word. Phones keep the bottom sheet. Tablets (`md` up to `lg`) keep the right-hand column. Opening a panel never shifts the text. The word card leads with the word, its part of speech, a round listen button and the meaning; under the meaning are three plain links (Longman, Webster, Bing Pictures, `src/lib/lookup-links.ts`) that open a new tab. The app never fetches them.
- One book = one shelf card: identity matching is in `src/lib/shelf-identity.ts`. `repairShelf()` (merge duplicates) and `refreshCovers()` (re-derive covers, catalog cover cache-busted by `cover.sha256`) run on load (`src/lib/shelf-repair.ts`).
- A new shelf is empty. The empty shelf is one line of text that opens Discover (`data-empty-discover`), not a filled button. Nothing else is shown there: no suggested book, no steps, no sample. Nothing is preinstalled. Alice has no special case. When the shelf has books, that find-books button is gone, and the shelf does not repeat the tab name as a page heading or show how many books there are. "All books" is visible only on a wide screen, under the continue card. Discover does not repeat its tab name, does not show the add-a-book hint, and does not stamp a word-list date under each card. Discover is a store page while nothing is searched or filtered: one large featured book (the newest), then sideways rows with "See all" (New books by the catalog `added` date, never by `updated`; Public-domain classics; the three largest series; no reading-level rows, since the Filter menu chooses a level), then the All books grid. The rows are `browseRails` in `src/lib/discover-rails.ts`. `added` is set once when a book first reaches the catalog and kept by `publish-word-list` and `publish-public-book`; `scripts/backfill-catalog-added.mjs` fills it for older rows. A row has no scrollbar: page dots under it (`data-rail-dots`, one per screen-wide page) follow the swipe and jump on tap. In a series, a book with no number (the Magic Tree House 1-4 collection) takes the first number in its title (`seriesPlace`). A row cover (`data-rail-book`) is not a list card, so the grid keeps exactly one `data-pack` / `data-word-list` card per book. "See all" opens that one collection with a back button. A cover opens the book detail sheet (`BookDetail` in `src/components/discover-browse.tsx`): Lexile, word, phrase and note counts, series number, ISBN, and the one action (add, open, update, try again). A book with no Lexile measure shows no level chip at all, never an "Unrated" label. On the shelf, "needs your e-book" and "book file needed" are a line of text under the author, never a tag on the cover art. The UI never calls a book free. The header shows the name inputread as text, with no icon, and has no bottom rule. Its icon buttons use a light stroke and do not fill in when selected. On the shelf and on Discover the search field is on that button's left, in the same row. On a phone the shelf does not put a continue-reading row above the books. The reader opens a book from the grid. Wide screens still show the large continue card. The header keeps a separate account button and a separate settings button. Settings has language, theme, a link into the account dialog, and the guide. It does not ask for a book-list address. The account dialog shows the email, the nickname, and logout. Export and delete sit under More.

On catalog load (app boot and Discover) `autoUpdateWordLists()` (`src/lib/word-list-update.ts`) only notices every installed book whose catalog `rev` changed. The shelf shows Update as a small accent tag on the book cover, the same size as Public domain, and a note at the top of the shelf (`data-lists-ready`) with those covers, what stays, and one Update all button (books one at a time, `updateInstalledBooks`). A toast says what changed after a tap (`announceListUpdate`). Discover keeps its cover control. The reader taps Update, and that tap replaces the glossary — EPUB, reading place, saved words and settings stay. The decisions are pure (`planListUpdate`, `checkListAgainstBook`, `wordListUpdateActions` in `src/lib/word-list-plan.ts`): a hand-added or edited list (`extras.source === "custom"`) is never replaced, not even by Update (that path skips `applyPackGlossary` and only moves the saved copy and the revision on), and its card says the edited list is kept instead of offering Update; a classic whose book file changed, or a word-list book whose new list matches the reader's EPUB under 80%, keeps the old list and shows Update with the reason. A stored list whose word count is not the catalog count still offers Update even when the revision string already matches (an older file paired from the device cache). Pairing (`fetchWordList`) uses a saved copy only when its sha256 is the catalog file.
- Global wordbook: one card per lemma (`src/lib/wordbook.ts`, `vocab-store.ts`), each with `sources[]` (book key, title, chapter, sentence, anchor). The SRS schedule fields are unchanged. Sync kind `wordbook` (27 letter shards) in `sync-merge.ts`/`sync-diff.ts`/`sync-engine.ts`; legacy per-book `words` items are folded in on pull and never rewritten.

Both fields stay optional, so an older save with neither or only one still loads. Never download or swap a book file for sync.
- Paragraph lightbulb: a PERMANENT small bulb (no hover-follow) next to every paragraph that owns a note, in the margin on wide screens and at the text edge on phones; geometry in `src/lib/paragraph-bulbs.ts` (`planBulbs`), drawn position-fixed by `ParagraphBulbs` in `help-panels.tsx` so the text never moves. The help panel uses the same owner. Senses with `trickyMeaning: true` get the wavy `book-tricky` mark only at the anchored token (`trickyAt`; boolean only).

The e2e ones need `npm run build:local` plus a preview server.
- PageUp / PageDown are handled by the reader ALWAYS, whether the page-turn setting is on or off. They mean "one page" in a reader, and the engine's own page scroll is `innerHeight` minus a small overlap - measured at 700px where our page was 576px on a 1280x800 window. The setting is OFF by default, so leaving those two keys to the browser put every reader back on the engine's scroll and silently bypassed all of the arithmetic below; that is why "PageDown turns too far" survived three fixes in a row. The setting governs only the keys that are page keys on some devices (volume keys, arrows, Space). `npm run test:paging` runs with the DEFAULT preferences now, not with the setting turned on.
- The page guard (`src/lib/page-guard.ts`, `watchPageMoves`) holds every turn to ONE of our pages, whoever scrolled. A run of scroll events with no finger, wheel, pointer or other key behind it that moved more than one page is put back to exactly one page from where it started: that is the browser's own page scroll on a page key or a volume key, alone (the page never sees the key) or on top of ours. A run that starts with our own turn (`turn()`) is always held; an input-less run the reader did not start is corrected only on a coarse pointer or an e-ink screen (a desktop find-in-page jumps with no input). A run during which the document height changed (the engine keeping text in place while a picture loads) is left alone. Every scroll the reader makes itself (restore, chapter change) calls `quiet()` first, or the guard would undo it. The restore hold listens for keydown in the CAPTURE phase, because the page keys stop propagating there. `npm run test:paging` checks a browser scroll on top of a turn.
- Page-turn mode is for the KEYBOARD and the reader's own page buttons, never for taps: a tap on the reading page opens a word or puts a card away. A page is a WHOLE number of lines MINUS `PAGE_KEEP_LINES` (4): `floor(visible / line) - 4` lines, `visible` = `min(innerHeight, visualViewport.height) - top bar`. Whole lines, because a bare pixel height leaves the first line of the new page cut in half under the bar; minus four, because `visible` is only what the engine SAYS is on the glass - an e-ink WebView runs its layout viewport under a native bar, so the Moaan MIX7 hides about three lines at the bottom and every turn lost them, so one line of margin is kept on top of that. Do not remove the tolerance to "make the arithmetic exact": it was exact, and the device still lost three lines. If a device still overshoots, do NOT raise that constant again first: it was raised to 42% of the screen and the device still overshot, which our own step cannot do. Open the book with `?probe=paging` (`/read/<id>?probe=paging`, `?probe=off` to clear) and read the line at the bottom: the key the device sent (none = the browser or the system turned the page, our handler never ran), our page, the visible height, and the last move. Two turns closer than `MIN_TURN_MS` (220ms) are one turn, because one press can reach the page twice (a key event plus a click, a repeated keydown without `repeat`).
- **A request has 10ms of CPU on the Pages Free plan, and that budget is a design constraint.** Measured in V8 + BoringSSL: PBKDF2-SHA256 at 100k iterations is 16.4ms, so every login, registration and password reset was cut off (error 1101, `exceededResources` in the dashboard); 10k is 1.7ms, which is what `PBKDF2_ITERATIONS` is now. A legacy 100k hash still verifies and is rewritten at the current count on the next successful sign-in. Do not raise it back without moving to Workers Paid. Batch sizes belong to the same budget and live in `src/lib/limits.ts` (`SYNC_PUSH_MAX`, `WORD_TAPS_MAX`), imported by both the client and the Function: the client splits its upload, the server refuses anything larger. Anonymous writes also count against `DAILY_WRITE_BUDGET` in `functions/lib/rate-limit.ts`, a daily fuse that answers 429 once the day's rows are spent, so a botnet cannot turn telemetry into a bill. A new endpoint that reads rows in a loop, parses a large body or hashes must be checked against this budget, and anything a signed-in account can trigger in a loop gets `assertUserRateLimit` (`/api/glossary`, `/api/sync`).
- **Every address that can answer with index.html needs a `Cache-Control: no-cache` rule in `public/_headers`.** `/read/<id>` did not have one: the browser kept a day-old page, the next deploy replaced the chunks it names, and the site was dead until a hard refresh while incognito (nothing cached) worked. `scripts/deploy-files.test.mjs` reads the routes out of `src/lib/router.ts` and fails when one has no rule. A catch-all `/*` will NOT do: matching header rules are merged, so it would add `no-cache` next to `/assets/*`'s `immutable` and stop the chunks caching. `index.html` also heals itself - a missing `/assets/*.js` reloads once with `?r=<timestamp>` (a different URL is what bypasses the browser cache) and gives up on the notice; `npm run test:boot` covers both the heal and the 'do not loop' case.
- `/assets` never goes through a Function. `public/_routes.json` includes `/api/*` only, so a page view costs zero Function calls for its scripts and styles; they used to run one invocation each through `functions/assets/[[path]].ts`, which is gone. The price is that `_redirects` lists the app's addresses one by one instead of `/*`: a catch-all also catches a missing `/assets/<hash>.js`, answers with index.html and status 200, and `/assets` is cached for a year - the blank page this project already had once. **A new screen needs a line there as well as a case in `src/lib/router.ts`; `scripts/deploy-files.test.mjs` fails when the two disagree.**
- Two builds come out of `vite build`: the module build, and a second ES5 copy (`@vitejs/plugin-legacy`) that the page picks up through `nomodule`. The Kindle browser ignores `<script type="module">` completely, so without that copy the page stayed white. Never remove the plugin, and never post-process `dist/index.html` in a way that drops the `nomodule` tags. Two settings keep the e-ink readers alive and both are easy to get wrong: `modernTargets` must repeat the `build.target` floor (chrome69), because without it the plugin compiles the modern bundle for chrome105 and puts `?.` and `??` back, which that WebView cannot parse at all; and `legacyOnlyWithoutModules()` (`scripts/vite-plugins.mjs`) must stay after the plugin, because it removes every `import.meta.resolve` probe the plugin writes - the two inline module scripts in `index.html` AND the guard `import 'data:text/javascript,...'` it prepends to the entry chunk. That method needs Chrome 105: the inline pair sent every Chrome 69-104 device into the ES5 build ON TOP of the modern one (two React roots in `#root`, a broken wide-screen layout), and the chunk guard ran before the app did, so the modern app never started at all (Chrome 83 on the Moaan e-reader: "Uncaught Error: import.meta.resolve not supported"). `npm run test:legacy` checks all of it. `index.html` also carries a small ES5 notice that appears after 12s only when nothing mounted, with the last errors, so a browser that still cannot run the app says why.
