# Margin Words: project notes

A static reader for English novels, for Chinese junior-high learners. It is a plain Vite + React 19 +
Tailwind 3 + zustand single-page app. It has no AI calls. The reader works fully with no account.
**Stay on Tailwind 3.** 4 needs Chrome 99 for `@layer` and Chrome 111 for the colours it emits, so
it cannot reach the Android e-ink readers some of these students use; v3 writes plain CSS with
physical properties. The theme tokens are the CSS variables in `src/styles.css`, each with an
`-rgb` twin so `bg-paper/90` still works (see `tailwind.config.js`).
**Visual design** follows the design system "Keep reading" (the user's claude.ai design-system artifact,
from 2026-10-29): it changes how things look, and the notebook and review pages were laid out anew.
All of it is in (PR #249). Its rules, in the code:
- Four reading themes on `<html data-theme>`: `light` (paper, default), `sepia`, `dark`, `eink`. The Clear
  theme was retired and reads as `light` (prefs merge, boot script, `asSettings`). Only paper and ink change
  between themes. Paper is pure white (only sepia keeps a warm page); the brand green (`accent`, #17804f on
  paper) is a little deeper on sepia, lighter at night, black on e-ink.
- Token names in the app vs the design: `muted` = ink-2 (secondary text), `faint` = ink-3 (meta only),
  `line` = rule (hairlines), `edge` (control borders, 3:1), `sheet` (the layer laid on the page), `card`
  (the word card), `accent` = brand, `accent-soft` = brand-tint, `mark` = saved / understood (never a
  selection colour), `warn` only for what needs the reader. Saved highlights use soft amber, with
  `mark-hover` and `mark-active` for interaction, and `mark-inverse` for readable amber actions on `bg-ink`.
  Word hints offer Subtle (muted-green ink, gray grounds on e-ink), Underline (solid/dashed/wavy), and Off.
  Saved words retain full-height backgrounds and ordinary ink in every mode. `wordHints` is canonical;
  `quietMarks` mirrors Off for older local preferences. Legacy true maps to Off, false/missing to Subtle.
  UI/reading preferences and language stay on this device: sync captures only review counts and reading
  days from the legacy settings item and never applies remote preferences. Signature format v2 ignores
  preference fields; an older cursor record triggers one full pull without dropping pending data.
- Radii: `rounded-sm` 2px (marks on text), `rounded`/`md`/`lg`/`xl` 10px (buttons, fields, chips, notices),
  `rounded-2xl`/`3xl` 16px (cards, dialogs, popovers), `rounded-cover` 6px (book covers), `rounded-card` /
  `rounded-t-sheet` for the word card only. No pills: `rounded-full` is for dots, switches, avatars and the spinner.
- Floating layers (dialogs, popovers, drawers): `bg-paper`, `rounded-2xl`, 1px `border-line`, `shadow-lift`,
  overlay `bg-black/[0.32]`. The word card has its own soft, wide `shadow-pop`. No frosted glass anywhere.
- Fonts: the book's own words (book titles, text, headwords, meanings, example sentences) are Literata
  (`font-display`), and so are big numbers (`font-display font-bold`, lining tabular figures); the
  interface, including page, section and dialog titles, is Atkinson Hyperlegible, titles `font-bold tracking-[-0.02em]` (400/700 only: `font-medium` renders 400,
  `font-semibold` 700). Literata falls back to a self-hosted Noto Serif SC subset for any Chinese (`src/fonts-zh-serif.css`, made by
  `scripts/subset-zh-serif.py` from the characters in `i18n-zh.ts`; characters added later fall back to the
  system serif until it is run again). Inter stays for IPA only.
- Icons: Lucide, stroke 1.5 everywhere (`.lucide` in styles.css). Current items turn `accent`, never filled.
- English runs about twice as long as Chinese. Button text never wraps (`whitespace-nowrap` in `btnBase`); a row
  that does not fit wraps whole items (tabs and quota, button and button), never overlaps or squeezes them.
  Only rows meant to scroll sideways (book rows) may run past the edge. Check a change at 320px in English.
- Current top-nav item: ink, bold, 2px accent line on the header's bottom edge (the item fills the 56px
  header). Phone tab bar (design system TopBar): 60px high, 22px icons over a 12px label, other tabs
  `faint`, the current one accent + bold with a 2px accent line at the top over the middle 40%, no pill.
  The Overview icon is the design's own bar-chart (`OverviewIcon` in `margin-app.tsx`). Anything that
  floats above the tab bar sits at `3.75rem` + the safe area. Sub-tabs: 2px accent line. Progress: a 2px
  line, square ends.
- E-ink: every animation and transition is off (end states only). Night: covers dim to 82%.
- Depth (design system v44): three levels, nothing in between. Flat: `sheet` (number tiles, setting
  groups), no shadow. Raised: `shadow-hero` = `--elev-2` (continue card, Discover's newest book, the
  review launcher). Floating: `bg-float` + `border-float-edge` + `shadow-lift` / `shadow-pop` =
  `--surface-3` / `--edge-3` / `--elev-3` (word card, book detail, panels, dialogs, menus, popovers).
  At night the higher layer is lighter with a faint light edge; on e-ink the levels are lines. Inside a
  floating layer `bg-sheet` is `--float-sheet` (ink 5% over the layer, mixed by hand: no color-mix),
  so a tile sits a step above its panel, never sunk into it. A new floating layer uses `bg-float`.
- Cover glow (`CoverGlow`, `.glow` / `.cover-glow`): the book's cover blurred (56px) and enlarged behind
  the continue card, the newest book and the top of the book detail. Dimmer at night, none on e-ink,
  with reduced transparency or for a book with no cover image. It loads the same request as the cover beside it
  (same URL, `crossOrigin` from `coverCrossOrigin`): a plain <img> was a second download of every cover,
  and its non-CORS cached copy can break the cover itself (cover-request.ts).
- Settings, account, reading settings on a phone and the share dialog share one panel (`panel` and
  `PanelHandle` in `ui.tsx`): a centred panel on a wide screen, a bottom sheet with a drag bar on a phone.
  Settings sit in groups: a 13px label over a `sheet` box of 52px rows split by hairlines, a note under it.
  The theme is chosen while reading from four small pages in each theme's own paper, ink and green
  (`ThemeTiles`) in the reader's Aa panel; account preferences have no theme picker. Switches are `Switch`.
- The reader's Aa panel (`reader-settings.tsx`): theme pages, three font cards ("Aa" in the font; the sans
  choice is Atkinson, key `sans`, no longer Inter), A buttons at the ends of the size slider, line spacing
  with a drawing of each gap, page width, a Focus switch and a full-width three-choice Word hints control. A popover with a point on
  a wide screen, a bottom sheet on a phone; every change shows at once in the page behind.
- The account dialog: a 64px round picture with a camera button, the nickname with a pencil that edits it
  in place, My reading (tiles and the words mastered, with Share), the word-list places as bars, and
  Export / Sign out / Delete as rows.
- Overview (`dashboard-page.tsx`, `overview-people.tsx`): a 52rem page, tabs with a sliding line, big
  numbers in Literata that count up and then get a highlighter (`HeroNumber`, `useCountUp` in
  `src/lib/count-up.ts`), the six counts as a ruled ledger, public-domain vs word lists as a two-part bar,
  the contributors as a ruled ranking (first place in highlighter) and supporters as an avatar grid.
  A ranking row keeps the reader's books on a phone too (`data-rank-books`: 3 covers then `+n`; 4 on a
  wide screen); the name column is `minmax(0,1fr)` so a long name cannot push them off the screen.
- A speech with no cover picture gets a drawn cover (`BookCover` "talk" / "ted", `.talk-cover` in
  styles.css, design system BookCover v48): a microphone and SPEECH at the top left (a TED talk: a fine
  outlined tag with our own stage drawing and "TALK · TED" in plain type, never TED's red, lettering or
  logo), faint sound rings from the top-right corner, the title in the lower half, the speaker, and a
  16-bar waveform worked out from the title (`talkWave`). The look comes from the catalog category and
  series (`coverLookOf`; series "TED"); the shelf learns it with the speech ids (`isTedBook`).
- Free-plan request budget. Opening and leaving a book inside the app costs no catalog, word-list or
  book download (all kept on the device). While a book is open its reading place uploads at most
  once a minute (`holdSyncPushes({ reading: true })` in the reader, `READING_DELAY_MS` in
  sync-pace.ts), not on every scroll pause: 12 scrolls used to be 12 `/api/sync` POSTs (Function
  calls and D1 writes). Leaving the book, hiding the tab and closing the page upload at once; an
  upload cut off by a closing page is marked dirty and runs on the next start. The catalogs go
  through one shared download per minute (`sharedJson` in src/lib/shared-fetch.ts): a page load
  used to ask for each catalog two or three times, each an R2 read. `scripts/request-budget.test.mjs`.
- The share image (`share-card.ts`) is 1080 x 1512: a finished book's cover large with an outlined amber
  seal (a double ring, the word and the month the book was finished, turned -12deg, half on the cover
  and half on the card, with a thin dark halo), or the finished covers fanned with three big numbers;
  paper (the book's own colour), forest and night. The footer is part of the card under one hairline:
  the wordmark, the line about the site and "Scan to read with me →" (brand green; light green on the
  dark styles) on the left, the QR on a small white tile on the right (`FOOTER`, 3.75x the design's
  288px preview). Its lines never wrap: a long English one gets smaller type before it is cut.
- The mark is three lines of text with one word lit by the highlighter, on dark green
  (`public/brand/`, `public/favicon.svg`; the one-colour mark is the tab icon on e-ink). The app header
  keeps the plain text wordmark. App icons are drawn by `scripts/make-app-icons.mjs`, the link picture by
  `scripts/make-og-image.mjs`.
Optional accounts (email, password, and sync of shelf, progress, saved words, and learning history) are
Cloudflare Pages Functions in `functions/` plus a D1 database. See [docs/ACCOUNTS.md](docs/ACCOUNTS.md).
Do not store ordinary user data in R2. Publicly projected contributor names and avatars are the documented
R2 exception; follow [docs/MAINTENANCE.md](docs/MAINTENANCE.md) for that surface. Books and word lists use
book-pack format for compatibility, but live copies are not in git. **The app has no file import**: books
are added only from Discover by a signed-in reader. A word-list book takes the reader's own EPUB from its
Discover card or restores the missing file from its existing shelf card; a standalone EPUB is never
imported as a new book. A verifiable matching file saves and opens automatically, including a trusted
private-library download; low/no-comparison matches need explicit confirmation. For upload identity, naming and
exact-byte rules, follow [docs/BOOK_UPLOAD.md#identity-and-naming](docs/BOOK_UPLOAD.md#identity-and-naming)
rather than copying those procedures here. New ids use meaningful full-title slugs (max 64 characters);
legacy ids and paths never migrate. Display full official titles and series names (official abbreviations
such as TED are allowed), and preserve the source EPUB filename-independent bytes and metadata.

## Rules

- Tailwind 3 puts every transform in one `transform` declaration (`--tw-translate-x/-y`, rotate, scale).
  A `@keyframes` that writes `transform` replaces that declaration whole, so the entrance animations
  repeat the translate: `pop-in` starts and ends with
  `translate(var(--tw-translate-x, 0px), var(--tw-translate-y, 0px)) scale(...)`. Drop it and a
  centered dialog paints its corner at the middle of the screen for the length of the animation and
  then jumps into place. Tailwind 4 did not have this problem (`-translate-x-1/2` was the separate
  `translate` property), so the mistake came in with the move to v3.

- The UI has two languages, `en` and `zh`. Every visible string (labels, aria-labels, toasts, errors) goes
  through `useT()` / `tr()` from `src/lib/i18n.ts` and lives in BOTH `src/lib/i18n-en.ts` (plain, simple English)
  and `src/lib/i18n-zh.ts` (simple Simplified Chinese for junior-high students). Both must have the same keys (tsc
  and `npm test` check this). Book content (meanings, paragraph/sentence help, phrases, titles) is English and is
  never translated.
- Chinese text is allowed ONLY in `src/lib/i18n-zh.ts`, `docs/` and `README.zh-CN.md`. No Chinese in other
  files of `src/`, `public/`, `packs/`, `examples/` or `scripts/`. `npm run check:cjk` must pass. (The Chinese
  text of the guide page in the app is in `docs/guide-chrome.json` and built into `dist/kit/`, never stored in `public/`.)
- Never change the reading layout when a panel opens. Panels are overlays. Test with a layout-shift run.
- The pack word lists (`packs/<id>/glossary.json`) are a frozen snapshot of book content (see "Where to
  work"). Do not edit or add them. `node scripts/build-packs.mjs --check` must still pass on what is there.
- No network call may depend on a server of ours except the optional account API on the same Pages
 host (`/api/*`, Pages Functions + D1). The reader may only fetch the catalog and pack files the user
 chose, plus that same-origin account API when someone is signed in. Book files stay on the books host.

- A spine file the chapter list already shows keeps its chapter index and paragraph indexes. Files the reader used to drop (and only those) are extras: own ids `x0`, `x1`, …, spine order, labelled Extra. Word anchors and phrase notes do not resolve on an extra. A contents file with zero paragraphs is not inserted as a numbered chapter. The following non-contents spine files, up to the next contents file, are one extra in that reading-order place, titled with the contents title (`fromToc` on `EpubExtra`). A contents title that is front matter (Cover, Title Page, Copyright, Contents, and the same kind of label) is not recovered: those following files stay separate extras, with the same ids as before. A sentence note may set `chapter` to a recovered id only when `fromToc` is set. A paragraph note may set `chapter` to any extra id (`x2`, `x3`, an appendix included) and is placed by the paragraph help-mark rule. A short heading file is not this case, and its split files stay ordinary extras. The empty or one-entry contents fallback (one spine file, one chapter) is unchanged and has no extras. Optional glossary field `"spine": { "merge": { "<dropped href or manifest id>": "<contents chapter href>" } }` appends a dropped file after that chapter's existing paragraphs (`applySpineMerge` in `src/lib/epub.ts`). The file's title is shown as a heading in front of the appended paragraphs when the file does not already have that heading. The heading is not a paragraph and its words are not counted (`data-merge-title`), so paragraph indexes and word occurrences stay put. A merge key may name the empty contents file or a content file absorbed into that extra; either name, or both, appends that extra once. A name that matches no spine item is a warning from the glossary check, and it names the key. A key that matches a spine item but merges nothing into or from that file warns too (`spine.merge key "<key>" matches a spine item but nothing is merged into or from it.`). The command-line check prints it, and the app shows it in the own-EPUB dialog (the one place a reader pairs a book with a list). The checker is `scripts/validate-glossary.mjs` in a git checkout, not in `dist/` or the kit zip: `node scripts/validate-glossary.mjs book.epub glossary.json` from the repository root. The validator accepts the field. Do not put it into a pack glossary by hand; teachers add it for the books that need it (Magic Tree House 33 `split_009`, Wings of Fire 3 `part0006_split_001` and `part0005_split_001`, Wings of Fire 4 `split_013`, Wings of Fire 5 `split_014`). Optional top-level `"segmentation": 2` splits a chapter-wrapper blockquote (a `calibre` class, or a blockquote that contains an `h1`–`h4`) into its headings and paragraphs (`skipNestedParagraph` in `src/lib/flow-text.ts`). Without that field a blockquote stays one paragraph, byte for byte the same as before, so a live note on `c2.p0` stays on `c2.p0`. Magic Tree House 33 sets the field. Magic Tree House 17 and 24 leave it off until their notes are re-anchored. `node scripts/seg-report.mjs <epub> <glossary.json>` prints chapter ids, segment ids, a hash per chapter, and whether segmentation is on.
- Glossary entries may carry `senseOnly: true` (optional boolean; docs/GLOSSARY_FORMAT.md 7.5, docs/book-pack-spec.md 4.7). Such an entry holds only position-based senses, and the reader underlines/opens the word ONLY at the places its senses name (`readingHtml`, `entryAppliesAt` in `src/lib/glossary-format.ts`). The flag must survive every copy of the list: validator (`validateGlossary`), `applyGlossary`, `applyPackGlossary`, and the stored `Gloss` in IndexedDB (`gloss:<bookId>`). `node scripts/sense-only-e2e.mjs` checks this end to end (needs the e2e preview server, see `scripts/e2e-ui.mjs`).
- For anyone (or any AI) who makes packs: `docs/book-pack-spec.md`. Keep it in step with `src/lib/glossary-format.ts`; `npm run check:example` validates its JSON example.

- Public-book admin writes are CPU-budget gated: `PUBLIC_BOOK_PUBLISH_CPU_CONFIRMED` must strictly equal `"true"`; otherwise both public book and public list endpoints reject before reading the body. Do not enable this setting as part of a site deploy or routine upload: first verify target-runtime CPU budget separately. A 16 MB limit is not proof of Pages Free 10 ms safety. Books UI uses one public multipart request; private uploads remain two steps with explicit partial failure. See Book upload §7 and Maintenance versions.

## App structure notes

- Pronunciation is one voice at a time, and every recording comes from `https://uapis.cn/api/v1/dictionary/audio` (`src/components/ui.tsx`). The request is keyless and public: no credential is shipped and no key rotation is used, and it is a direct `<audio src>` because a JavaScript `fetch()` from a different origin fails CORS. Explicit UK/US IPA controls ask for `accent=uk` or `accent=us` and never substitute the other accent, a generic recording, or SpeechSynthesis; they show visible failure with retry when media does not start. Generic `speakEnglish` reads the persisted Settings pronunciation preference (US by default), tries that accent before the other uapis accent, and only then uses a device English voice preferring the selected accent. The audio element is APPENDED to the document (hidden) before `play()` because detached audio does not start on some Android WebViews. The query keeps every letter - `voiceText` trims edge punctuation but preserves Unicode such as `café` - and the IPA itself is never sent. `npm run test:pronounce` covers generic phrase/plain-word playback, fallback order, direct URL/accent mapping, attached media, errors/timeouts, cancellation and stale callbacks. The provider rate-limits dynamically rather than exposing a fixed daily allowance; the client makes one request per tap and does not auto-retry in a loop.
- `src/lib/polyfills.ts` only runs because `main.tsx` CALLS `installPolyfills()`. `package.json` says `sideEffects: false`, so a bare `import "@/lib/polyfills"` is dropped from the bundle: the shelf kept working (it touches nothing newer) and opening a book threw `Object.fromEntries is not a function`, a white page with no message. Keep the call, and add a polyfill here - not a newer API - when a device needs one. `crypto.randomUUID` (Chrome 92) is polyfilled there because adding a book and saving a word mint ids with it.
- Routes: `/shelf`, `/discover` (also `/discover/novels/`, `/discover/speeches/`), `/book/<catalog id>/` (Discover with that book open), `/dashboard`, `/guide`, `/words`, `/read/<bookId>` (`src/lib/router.ts`, History API; `/` redirects to `/shelf`). The menu is Shelf, Discover, then Overview last. The notebook is a small header button, not a tab. Language is chosen in Settings, not in the header. Overview is `/dashboard`. `/about` is the old About page and opens `/guide`. `/thanks` opens `/dashboard`. The supporters stay at the bottom of the Overview page as one quiet line — names without amounts, plus a count (`{n} supporters`) — with a small `Support us` link that opens the sponsor dialog: the gift is a public-interest donation, the reader picks WeChat, Alipay, or cryptocurrency, and the official address `xcrunnnn@outlook.com` is shown. The thank-you name is the account nickname. The dialog does not ask for another name. Amounts are never shown outside /admin. The site does not take payment and does not email. `/admin` lists requests for that admin account only. The admin ticks email sent, types a USD amount, and ticks the row onto the list. Repeat gifts add up. The six library counts are the visual center of the page, shown large. The page fits one screen. The notebook button does not show a due count. The Guide is opened from Settings, not from the menu. Pages are lazy chunks. `public/_redirects` rewrites each app address to `/` (never to `/index.html`, which Pages silently ignores as a loop) and `public/404.html` answers every other miss with status 404; `public/_headers` sets `no-cache` for the shell and `immutable` for `/assets/*`. The service worker does not answer requests, so a normal refresh is the browser's own load. On activate it turns navigation preload off, claims clients, then deletes every cache. `_headers`/`_redirects` are never part of the app shell. The static kit page is `/kit/`.
- On wide screens (`lg`, 1024px and up) the reading column stays centered at the text-width setting. The word, phrase, and paragraph cards float over the text near the tapped word and do not cover that word. Phones keep the bottom sheet. Tablets (`md` up to `lg`) keep the right-hand column. - PageUp / PageDown are handled by the reader ALWAYS, whether the page-turn setting is on or off. They mean "one page" in a reader, and the engine's own page scroll is `innerHeight` minus a small overlap - measured at 700px where our page was 576px on a 1280x800 window. The setting is OFF by default, so leaving those two keys to the browser put every reader back on the engine's scroll and silently bypassed all of the arithmetic below; that is why "PageDown turns too far" survived three fixes in a row. - The page guard (`src/lib/page-guard.ts`, `watchPageMoves`) holds every turn to ONE of our pages, whoever scrolled. A run of scroll events with no finger, wheel, pointer or other key behind it that moved more than one page is put back to exactly one page from where it started: that is the browser's own page scroll on a page key or a volume key, alone (the page never sees the key) or on top of ours. A run that starts with our own turn (`turn()`) is always held; an input-less run the reader did not start is corrected only on a coarse pointer or an e-ink screen (a desktop find-in-page jumps with no input). A run during which the document height changed (the engine keeping text in place while a picture loads) is left alone. Every scroll the reader makes itself (restore, chapter change) calls `quiet()` first, or the guard would undo it. - Page-turn mode is for the KEYBOARD and the reader's own page buttons, never for taps: a tap on the reading page opens a word or puts a card away. A page is a WHOLE number of lines MINUS `PAGE_KEEP_LINES` (4): `floor(visible / line) - 4` lines, `visible` = `min(innerHeight, visualViewport.height) - top bar`. Whole lines, because a bare pixel height leaves the first line of the new page cut in half under the bar; minus four, because `visible` is only what the engine SAYS is on the glass - an e-ink WebView runs its layout viewport under a native bar, so the Moaan MIX7 hides about three lines at the bottom and every turn lost them, so one line of margin is kept on top of that. Do not remove the tolerance to "make the arithmetic exact": it was exact, and the device still lost three lines. If a device still overshoots, do NOT raise that constant again first: it was raised to 42% of the screen and the device still overshot, which our own step cannot do. Open the book with `?probe=paging` (`/read/<id>?probe=paging`, `?probe=off` to clear) and read the line at the bottom: the key the device sent (none = the browser or the system turned the page, our handler never ran), our page, the visible height, and the last move. Two turns closer than `MIN_TURN_MS` (220ms) are one turn, because one press can reach the page twice (a key event plus a click, a repeated keydown without `repeat`).
- **A request has 10ms of CPU on the Pages Free plan, and that budget is a design constraint.** Measured in V8 + BoringSSL: PBKDF2-SHA256 at 100k iterations is 16.4ms, so every login, registration and password reset was cut off (error 1101, `exceededResources` in the dashboard); 10k is 1.7ms, which is what `PBKDF2_ITERATIONS` is now. A legacy 100k hash still verifies and is rewritten at the current count on the next successful sign-in. Do not raise it back without moving to Workers Paid. Batch sizes belong to the same budget and live in `src/lib/limits.ts` (`SYNC_PUSH_MAX`, `WORD_TAPS_MAX`), imported by both the client and the Function: the client splits its upload, the server refuses anything larger. Anonymous writes also count against `DAILY_WRITE_BUDGET` in `functions/lib/rate-limit.ts`, a daily fuse that answers 429 once the day's rows are spent, so a botnet cannot turn telemetry into a bill. A new endpoint that reads rows in a loop, parses a large body or hashes must be checked against this budget, and anything a signed-in account can trigger in a loop gets `assertUserRateLimit` (`/api/glossary`, `/api/sync`).
- **Search engines.** The keyword order is: English reader, then English original-book reader, then comprehensible-input reader. The Chinese title, description, keywords, JSON-LD and a plain-HTML introduction live in `docs/seo.json`; `scripts/seo-plugin.mjs` builds them into `dist/index.html` (the introduction goes inside `#root`, React replaces it on mount, and `html[data-js]` hides it so readers never see it) and writes `dist/sitemap.xml`. `index.html`'s boot notice counts the app as mounted only once `#seo-intro` is gone. The title, canonical address (always `https://inputread.site`) and `noindex` of each screen come from `src/lib/page-meta.ts`; the home page keeps the title from `docs/seo.json`. `public/robots.txt` keeps `/words/`, `/review/`, `/read/`, `/admin/` and `/api/` out, and `public/_headers` sends `X-Robots-Tag: noindex` on `*.pages.dev`. A new public screen needs a line in the sitemap list of `docs/seo.json` and a case in `pageMeta`; `scripts/seo.test.mjs` checks all of it. **Link previews and book pages:** every page carries Open Graph / Twitter tags; the site picture is `public/social/og.png` (redraw it with `node scripts/make-og-image.mjs` after changing `ogImageText`). The build also writes one page per Discover tab (`/discover/`, `/discover/novels/`, `/discover/speeches/`) and one per catalog book (`/book/<id>/`, the cover as its preview, the Chinese summary as its text) from the live catalogs (`scripts/seo-pages.mjs`); a production build that cannot read them stops (`SEO_BOOK_PAGES=skip` builds without), `build:local` uses the local folders. Pages applies a `_redirects` rule even when a file exists, so those addresses must never get a rewrite (`STATIC_PAGE_SOURCES`, checked by `scripts/deploy-files.test.mjs`). In the app, `/discover/<tab>/` is the Discover tab and `/book/<id>/` opens that book's detail; the detail's Share this book gives that address. A book added to the catalog gets its page with the next deploy.
- **Every address that can answer with index.html needs a `Cache-Control: no-cache` rule in `public/_headers`.** `/read/<id>` did not have one: the browser kept a day-old page, the next deploy replaced the chunks it names, and the site was dead until a hard refresh while incognito (nothing cached) worked. `scripts/deploy-files.test.mjs` reads the routes out of `src/lib/router.ts` and fails when one has no rule. A catch-all `/*` will NOT do: matching header rules are merged, so it would add `no-cache` next to `/assets/*`'s `immutable` and stop the chunks caching. `index.html` also heals itself - a missing `/assets/*.js` reloads once with `?r=<timestamp>` (a different URL is what bypasses the browser cache) and gives up on the notice; `npm run test:boot` covers both the heal and the 'do not loop' case.
- `/assets` never goes through a Function. `public/_routes.json` includes `/api/*` only, so a page view costs zero Function calls for its scripts and styles; they used to run one invocation each through `functions/assets/[[path]].ts`, which is gone. The price is that `_redirects` lists the app's addresses one by one instead of `/*`: a catch-all also catches a missing `/assets/<hash>.js`, answers with index.html and status 200, and `/assets` is cached for a year - the blank page this project already had once. Those rules rewrite to `/`: Pages drops a rule whose target is `/index.html`. For a long time every one of them was dropped and the screens opened only through Pages' own single-page fallback, which also answered missing assets with the page; `public/404.html` turns that fallback off, so the rules must work (the deploy-files test checks the target). **A new screen needs a line there as well as a case in `src/lib/router.ts`; `scripts/deploy-files.test.mjs` fails when the two disagree.**
- Two builds come out of `vite build`: the module build, and a second ES5 copy (`@vitejs/plugin-legacy`) that the page picks up through `nomodule`. The Kindle browser ignores `<script type="module">` completely, so without that copy the page stayed white. Never remove the plugin, and never post-process `dist/index.html` in a way that drops the `nomodule` tags. Two settings keep the e-ink readers alive and both are easy to get wrong: `modernTargets` must repeat the `build.target` floor (chrome69), because without it the plugin compiles the modern bundle for chrome105 and puts `?.` and `??` back, which that WebView cannot parse at all; and `legacyOnlyWithoutModules()` (`scripts/vite-plugins.mjs`) must stay after the plugin, because it removes every `import.meta.resolve` probe the plugin writes - the two inline module scripts in `index.html` AND the guard `import 'data:text/javascript,...'` it prepends to the entry chunk. That method needs Chrome 105: the inline pair sent every Chrome 69-104 device into the ES5 build ON TOP of the modern one (two React roots in `#root`, a broken wide-screen layout), and the chunk guard ran before the app did, so the modern app never started at all (Chrome 83 on the Moaan e-reader: "Uncaught Error: import.meta.resolve not supported"). `npm run test:legacy` checks all of it. `index.html` also carries a small ES5 notice that appears after 12s only when nothing mounted, with the last errors, so a browser that still cannot run the app says why.
